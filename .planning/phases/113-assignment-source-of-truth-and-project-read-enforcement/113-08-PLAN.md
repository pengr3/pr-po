<objective>
Repoint the Assignments tab so its checkbox grid writes the authoritative record directly, and repoint the two display surfaces that currently read the frozen arrays.

This is the write-side half of the phase. Today the tab writes `assigned_project_codes` onto a USER document and then fire-and-forgets a reverse sync (`syncAssignmentToPersonnel`, `assignments.js:652-703`) to push `personnel_user_ids` back onto the PROJECT documents. Under the personnel-authoritative model there is exactly one write per assignment and it goes straight to the container.

D-06 explicitly supersedes the mco lock on `saveManageModal`. That lock existed to avoid the `all_projects:false` landmine while the arrays were still authoritative; once the arrays are no longer read, the landmine is gone. The supersede must be recorded in the code, not just in planning docs.

D-05's safety argument, confirmed against the write rules by RESEARCH.md: `getVisibleSubTabs()` (`assignments.js:45-56`) never shows `services_admin` the Projects sub-tab and never shows `operations_admin` the Services sub-tab, so the only actors who can reach a repointed projects save are `operations_admin` / `super_admin` (both unrestricted `projects` update roles) and the only actors who can reach a services save are `services_admin` / `super_admin` (both unrestricted `services` update roles). No new capability is introduced.

Purpose: one authoritative write, no silent failure, and display surfaces that tell the truth.
Output: an Assignments tab that is a thin editor over `personnel_user_ids`.
</objective>
