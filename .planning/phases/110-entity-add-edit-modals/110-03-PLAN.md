<objective>
Create `app/entity-edit-modal.js` — a dedicated, pre-filled EDIT modal for Projects and Services (D-06). New Engagement is create-only, so it cannot serve edit; this module replaces the current mechanism where `editProject`/`editService` reuse the inline `#addProjectForm`/`#addServiceForm` (flip title + swap the submit handler). Plans 05/06 wire the list Edit buttons to these exports and delete the inline forms.

The field set and write logic mirror the current edit path exactly (D-06): client, name, location, status, budget, contract cost, collection tranches (`renderTrancheBuilder`), personnel pills — pre-filled from the record; write via `updateDoc` (NOT `createEngagement`). Existing working behavior is preserved verbatim: the `recordEditHistory` diff, the tranche sum-to-100 check, the existing-collectibles `confirm()` guard (which is a business-rule confirm, NOT the modal-close confirm that D-03 forbids), and the personnel assignment sync — **branched by kind**: PROJECT edits call `syncPersonnelToAssignments` (writes users' `assigned_project_codes`); SERVICE edits call `syncServicePersonnelToAssignments` (writes users' `assigned_service_codes`). These are NOT interchangeable — using the project sync for a service writes service codes into `assigned_project_codes` and silently corrupts production data (no staging env). Free close per D-03, toast validation per D-02, escapeHTML on all user strings.

**Critical correctness callout (Draft):** `projects.js` `UNIFIED_STATUS_OPTIONS` (projects.js:34) does NOT include `'Draft'`, but `services.js` (services.js:36) DOES. Since D-04 makes new projects start as Draft, this module MUST use a status option list that includes `'Draft'` for BOTH variants — otherwise a just-created Draft project cannot be opened/saved in the edit modal (no matching option + validation rejection). Define one `ENGAGEMENT_STATUS_OPTIONS` (the 11-value services.js list including Draft) and use it for both.

Purpose: give Plans 05/06 `openProjectEditModal`/`openServiceEditModal` so the lists can retire inline edit.
Output: `app/entity-edit-modal.js`.
</objective>
