# Phase 106 — AUDIT-01: Firestore SDK Call-Site Inventory

**The shared anchor map.** This is the exhaustive `file:line` index of every Firestore SDK
call site across the whole `app/` data layer (D-09). Plans 03-06 (integrity / correctness /
efficiency / security-rules dimension audits) read the anchors here and jump straight to the
cited lines instead of re-scanning 18k+ lines of view code (procurement.js 9,549 · finance.js
6,851). Plan 07 turns this into the report's inventory summary.

## How to read this file

1. **[Per-Operation Totals](#per-operation-totals)** — call-site counts per operation, each with
   a one-line note and the standing efficiency/integrity LEADS.
2. **[Per-File Matrix](#per-file-matrix)** — reads / writes / listeners / `destroy()` per app JS
   file; the surface map the dimension plans slice, with LISTENER-LIFECYCLE leads flagged.
3. **[Per-Collection Access Map](#per-collection-access-map)** — reads / writes / access-mode /
   files per collection (21+1 top-level literals + 6 subcollections); the map Plan 06 reconciles
   against `firestore.rules` (D-10).
4. **[Raw Call-Site Index](#raw-call-site-index)** — every hit as `file:line — trimmed line`,
   grouped by operation. **949 file:line anchors.** This is the grep target (`\.js:[0-9]`).

## Method & scope

- **Grep-based, exhaustive** over `app/**/*.js` only. `grep -rnE "\bOP\("` for each operation —
  the paren filters out `import { OP }` re-export lines so the counts are **call sites**, not
  substrings (the report must count call sites; see the substring gap below).
- **Excluded (D-11):** `archive/` (reference-only per CLAUDE.md), `.claude/worktrees/` (duplicate
  working copies), node `scripts/` as app code (`scripts/verify-integrity.js` is tooling we
  extend, not app code we audit). `firestore.rules` is audited by Plan 06, not inventoried here.
- **`diagnostics.js` included (D-09):** it reaches `client_errors` via
  `await import('./firebase.js')` then `addDoc(collection(db,'client_errors'), …)` (diagnostics.js:108)
  — a `from './firebase.js'` importer grep misses it; it is captured explicitly.
- **Subcollection / dynamic paths included (D-10):** `activity_entries`, `progress_updates`,
  `issues`, `baselines`, `audit_log`, and `edit_history` are reached via
  `collection(db, <parent>, <id>, '<sub>')`, `doc(db, …, '<sub>', <id>)`, or ref-variable
  indirection (`edit_history` under a **dynamic** `{collectionName}` parent) — none show up in a
  naive `collection(db,'X')` grep.

## Standing LEADS (handed to the dimension plans)

- **`runTransaction = 0` across `app/` → Plan 03 (integrity, High candidate).** Sequential IDs
  (MRF/PR/PO/TR/RFP + task ids) are generated by max-scan of existing docs with no transaction —
  concurrent-submit race is real. See `coll-id.js`, `task-id.js`, `service-task-id.js`,
  `proposal-id.js`, and the inline max-scan in `procurement.js` / `mrf-form.js`.
- **`where` 182 vs `limit` 12 imbalance → Plan 05 (efficiency).** All 12 `limit()` calls are on
  `notifications` (6) and journal subcollections (6, `limit(50)`). **Zero** of the ~15
  whole-collection listeners — `onSnapshot(collection(db,'pos'|'rfps'|'projects'|'collectibles'|'services'|'clients'|'suppliers'))` — are bounded.
- **Listener lifecycle → Plan 04 (correctness).** 8 of the 18 `onSnapshot` files do **not** use the
  CLAUDE.md-canonical `listeners[]` array; they use ad-hoc named unsubscribe handles (and `home.js`
  has 3 local-`const` listeners). See the Per-File Matrix `LISTENER-LIFECYCLE LEAD` flags.
- **Subcollection D-10 trap → Plan 06 (security-rules).** `audit_log` and `edit_history` are reached
  **only** via subcollection / dynamic-path writes; a top-level `collection(db,'X')` grep would
  falsely report their rule blocks as unused.

## Substring-vs-call-site gap (why the report counts call sites)

Raw substring counts inflate because `import { … }` re-export lines and longer identifiers contain
the substring: **`onSnapshot` 144 substring → 61 call sites**; **`getDoc` 241 substring → 54 call
sites** (`getDocs(` contains `getDoc`). Every count in this inventory is a `\bOP\(` **call site**.
