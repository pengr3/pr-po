# Phase 107 — UI Design Contract

> Visual and interaction contract for the Home **Command Center shell + feed engine**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of truth:** the existing CLMC design system (`styles/main.css` `:root`, `styles/components.css`, `styles/views.css`) + the spike 041 mockup (`.planning/spikes/041-home-paradigm-reimagine/spike.html`). This phase **reuses** that system; it declares only the NET-NEW tokens the Command Center needs, each mapped onto an existing variable.
>
> **Scope reminder:** shell composition + feed **engine** as a reusable frame + a 3-source seed (D-10/D-12). Per-role feed *definitions* (HOME-09–13 → Phase 108), Executive Dashboard (Phase 109), and the ≤768px mobile layout (Phase 111) are **out of scope** and are noted "deferred" where they touch a boundary.

## Feed Row Anatomy & Severity Tiers (the engine's visual contract) — D-05/06/07

A single **flat, severity-ranked** list. Engine sorts **critical → high → medium**, then most-overdue / newest-first within a tier (D-06). Source-agnostic (D-11).

### Row anatomy (left → right)

```
│▌ [icon]  Title (15px/600 ink)                                   [age 12px faint]
│▌         Subtitle (13px/400 muted)   [category chip 11px]
```

- **Severity rail** — 4px left border in the tier color (table below). The row's primary severity signal.
- **Type icon** — 20px inline-SVG (Heroicons style). Reuse the matching `TYPE_META[...].icon`; fall back to a same-style new path if a source has no notification analogue. Icon color follows the tier's icon emphasis.
- **Title** — one line, `text-overflow: ellipsis`.
- **Subtitle** — supporting context (who / what / amount), one line.
- **Category chip** — small tonal pill on the subtitle line (taxonomy below).
- **Age** — right-aligned, `nowrap`: `just now` / `${m}m` / `${h}h` / `${d}d` (age-in-stage or age-since-event; the source declares the timestamp).
- Row: `padding: 12px 14px`, `min-height: 44px`, `border-bottom: 1px solid #f1f5f9`, `cursor: pointer`.

### Severity tiers

| Tier | Rail | Row tint (rest) | Icon + age |
|------|------|-----------------|------------|
| critical | `--cc-critical` #ea4335 | `--cc-critical-tint` #fef2f2 | `--danger-dark` |
| high | `--cc-high` #f59e0b | `--cc-high-tint` #fffbeb | `--warning-dark` |
| medium | `--cc-medium` #1a73e8 | white → `--cc-hover` #f8fafc on hover | blue / `--cc-faint` |

### Category-chip taxonomy (the small chip on each row)

The chip encodes **domain identity** (quiet, tonal) — kept visually distinct from **severity** (the rail) so color isn't double-encoded. Reuse `badge` sizing (`padding:.2rem .5rem; border-radius:999px; font-size:.6875rem; font-weight:600; nowrap`).

| category | chip label | fill / text |
|----------|-----------|-------------|
| `proposal` | Proposal | `#e8f0fe` / `#1a73e8` (badge-primary) |
| `mrf` | MRF | `#e5e7eb` / `#374151` (badge-secondary) |
| `pr` / `tr` | PR / TR | `#eef2ff` / `#4338ca` |
| `po` | PO | `#e0f2fe` / `#0369a1` |
| `finance` | Finance | `#ecfdf5` / `#047857` |
| `rfp` | RFP | `#fffbeb` / `#b45309` |
| `project` | Project | `#e8f0fe` / `#1a73e8` |
| `service` | Service | `#f0fdfa` / `#0f766e` |
| `issue` | Issue | `#fef2f2` / `#b91c1c` |
| `dlp` | DLP | `#fffbeb` / `#b45309` |

**107 seed sources use only `proposal` and `mrf`.** The full taxonomy is declared so Phase 108 sources plug in without inventing new chip styles.

### Cap, expander, and roll-up (D-05)

- Show **up to 8** rows collapsed. If total > 8, render a footer expander **`Show all (N)`** (blue link) that reveals the remainder up to a **hard safety cap of 25**; expanded footer reads **`Show less`**. Beyond 25: append a muted line `Showing 25 of N — open the relevant area to see the rest.`
- **Roll-up rule of thumb:** when **≥5 items share the same `category`**, render the first 3 individually, then a single collapsed sub-row **`+${N-3} more ${categoryLabel}`** (medium severity, links to that category's list). Keeps the hero scannable. (107 seed volume is small; this is the documented rule for 108.)

### Dedupe / collapse (D-11)

- Every item carries a stable **`dedupeKey`** (e.g. `proposal-approval:{proposalId}`, `mrf-rejected:{mrfId}`).
- The engine **dedupes by `dedupeKey`, keeping the highest-severity instance** when the same record surfaces from two sources; the lower-severity duplicate is dropped.
- No time-window merging in 107 beyond the roll-up rule above.

### Deep-link / interaction contract (D-07)

Each item declares **one** target of two kinds; the engine supports both, the source chooses:
1. **route-hash** → sets `location.hash` (e.g. `#/finance`, `#/procurement/records`).
2. **modal-action** → invokes a registered `window.*` handler in place (e.g. `window.homeQueueOpenApproveModal(id)` / `...RejectModal(id)` for proposal approval — reuses `_openHomeQueueModal`; **no new destructive UI invented**).

Interaction:
- **Whole row** is the click target.
- Hover: background → tier hover wash, slight affordance (no transform jitter; a 1px inset or bg change is enough).
- **Keyboard/a11y:** each row `role="button"`, `tabindex="0"`, activatable by **Enter/Space**; `aria-label` = title + severity + age. Visible focus ring (2px `--primary` outline).

### Refresh (D-08)

Right-aligned control in the feed section header: **`↻ Refresh`** (`.btn-ghost`, small) + caption **`Updated ${relTime}`** (e.g. `Updated just now`, `Updated 4m ago`) in `--cc-faint`. Click re-runs the batched compute-on-load fetch. **No persistent listener fleet** across source collections (D-08 / 106 finding). If any listener is ever added, it must clear-before-push and tear down in `destroy()`.
