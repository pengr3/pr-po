<plan_assertions_proven_wrong>
Two acceptance criteria in `114-01-PLAN.md` Task 2 are factually wrong. They must be
recorded as deviations in the SUMMARY, not silently satisfied or silently skipped.

**1. The `grep -c … == 0` variant test is invalid.**
The plan asserts `grep -c "replayIntegration"`, `grep -c "browserTracingIntegration"`, and
`grep -c "feedbackIntegration"` each output `0`. On the real error-only bundle they each
output `1`. The matches are *shim stubs*, not implementations:

```
t.replayIntegration=function(t){return u(()=>{console.warn("You are using replayIntegration() even though this bundle does not include replay.")})…
const Vr=t=>(u(()=>{console.warn("You are using browserTracingIntegration() even though this bundle does not include tracing.")})…
Xr=Object.assign(t=>(u(()=>{console.warn("You are using feedbackIntegration() even though this bundle does not include feedback.")})…
```

The presence of those `console.warn` strings is *positive proof* the bundle is the error-only
variant — the tracing/replay/feedback bundles contain the real implementations and no such
warning. **Corrected assertion:** each name appears, and appears adjacent to
`even though this bundle does not include`. Combined with the 90,586-byte size (a
tracing+replay bundle is ~3x), the wrong-variant threat (T-114-02) is mitigated.

**2. The jsDelivr two-source cross-check is structurally impossible.**
`https://cdn.jsdelivr.net/npm/@sentry/browser@10.70.0/build/bundle.min.js` returns **404**.
This is not a transient CDN miss — the npm package ships **zero** `.min.js` files
(204 `.js` files, all under `build/npm/`, verified via the jsDelivr package-file API). The
prebuilt CDN bundles are published only to `browser.sentry-cdn.com`. The GitHub release
tarball `sentry-browser-10.70.0.tgz` was also checked: 0 matching bundle files.

**Conclusion:** no second origin serves these bytes, so two-source provenance cannot be
established for this artifact by any route. Record it in the SUMMARY as a **residual
supply-chain risk** against T-114-01 (the plan explicitly requires this and forbids
proceeding as if it matched). Compensating control actually achieved: the committed bytes
were re-fetched from `browser.sentry-cdn.com` and are byte-identical (`cmp` clean) to the
repo copy, and the SHA-384 above is recorded here and (per 114-04) in `CLAUDE.md`.
</plan_assertions_proven_wrong>
