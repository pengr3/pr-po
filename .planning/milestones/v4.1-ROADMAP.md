## Phase 113 — Assignment Source-of-Truth and Project Read Enforcement

**Goal**: Make `personnel_user_ids` the single authoritative record for cross-department assignment
visibility, retire the two fire-and-forget sync pipelines maintaining the derived
`assigned_project_codes` / `assigned_service_codes` arrays, and enforce `projects` read scoping
server-side instead of as cosmetic client-side filtering.

**Why now**: Live production defect — a `services_user` assigned to a project via the Personnel
panel could not see it. Fourth recurrence of the bug class; the three prior quick fixes each
patched a read or UI layer without auditing the write layer. Debug trail:
`.planning/debug/services-user-project-hidden.md`.

verification gate — additive server changes first, client conversions second, tightening last.
